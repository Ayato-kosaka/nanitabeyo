# Daily Ops

**このスキルは判断を持たない。** 入口を列挙し、担当スキルへ渡し、
「今日は何もない」と言い切れるかを決めるだけ。

判断の中身をここへ書き足さないこと。書きたくなったら、それは担当スキル側の知識である。

## ⚠️ 定期実行しない

**cron で自動起動しない。** オーナーの指示で起動する。

理由は 2 つある。

1. **トークン**。何も無い日にセッションを起こすと、状況確認だけで数万トークン消える。
   実測 2026-08-23: `mcp__github__actions_list` の run 一覧は 1 回で約 30,000 トークン
   （コミットメッセージを全文返すため）。「巡回するだけ」が一番高くつく
2. **状態はセッションではなく GitHub 側に置く**方針だから。起きていること自体に意味が無い

集計だけは自動でよい。**Claude を起こさない日次ワークフローが Issue を作り、
Claude はオーナーに呼ばれたときにその Issue から読む。** こうすると、
どのセッションから再開しても続きができる。

### 探し方は git と Issue で済ませる

**`list_workflow_runs` で run 一覧を舐めない**（上記のとおり高い）。
PR の状態は `pull_request_read` の `get_check_runs`、ブランチの進捗は
`git log -1 --format='%h %cr %s' origin/<branch>` で見る。
詳細は [`parallel-development/CORE.md`](../parallel-development/CORE.md) の「runを追跡する」。

## 渡し方

**担当スキルを読んでから作業する。** ここに書いてある要約で判断しない。

1 件ずつ、次の 3 つを決めてから着手する。

- **今日中に終わるか。** 終わらないなら、今日やる部分を切り出して Issue に書く
- **オーナーの判断が要るか。** 要るなら**先に投げる**。判断待ちの間に他の入口を進める
- **不可逆か。** 削除・デプロイ・マイグレーション・外部への公開は
  **必ず承認を取ってから**。承認は 1 回ぶんで、次の同種操作には効かない

## 「今日は何もない」と言い切ってよい条件

次を**すべて**満たしたときだけ、何もせずに終えてよい。1 つでも欠けたら
「確認できていない」であって「何もない」ではない。

- [ ] 入口 1〜5 をすべて見た（見ていない入口があるなら、そう言う）
- [ ] open の `error-triage` / `content-report` Issue が 0 件
- [ ] 自分が開いた PR がすべて **緑かつマージ可能**（赤い PR を「レビュー待ち」と呼ばない）
- [ ] オーナーへ投げた判断待ちが、投げっぱなしになっていない（何を待っているか言える）
- [ ] `オーナー確認待ち` の Issue を数えた（0 件でないなら、何が待たされているか言える）

**「たぶん無い」で終えない。** 数えられないものは「数えられなかった」と言う。
