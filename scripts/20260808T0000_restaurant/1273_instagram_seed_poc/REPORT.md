# Instagram 初期シード PoC — 4.X ごとの実測（2026-08-28）

判定条件は **(a) 無料であること / (b) 50万店舗以上 × 132 料理カテゴリを充足すること**。
生の測定値は [`out/`](out/) に置いてある。

**オーナー指示により 4.6 / 4.7 / 4.9 / 4.10 / 4.12 / 4.13 / 4.15〜4.19 は対象外。**

## 0. 結論 — 打開策は 4 本。うち 1 本で条件(b) に届く

当初の «アカウント経路は全部足しても約 4 万本» という壁は、次で抜けられる。

| | 打開策 | 実測 | 費用 |
| --- | --- | --- | ---: |
| **B-店** | **店名で «その店の投稿» を直接引く** | **88% の店で投稿が見つかり、目視補正後 42.4% で店名が確認できる → 全国 約 499,000 店** | **$0.30 / 1,000 クエリ** |
| **B-面** | Web 検索でカテゴリ×地域から採る | **108 セル全部**で «対象地域 5 本以上» を満たす。1 セル 10 ページで **64〜86 本** | 同上 |
| **A** | **`business_discovery` は App Review 無しで通る** | 既知ハンドルの **75.0%** が解決、投稿数 **中央値 276 本/店** | 無料（**200 コール/時**） |
| **C** | **Common Crawl で店舗公式サイトを無料代替** | 60 ホスト中 **40 が CC 内**、**11（18.3%）から Instagram リンク** | 無料 |

**条件 (b)（50 万店）は B-店で届く目算が立った。約 499,000 店で、ちょうど境界線上である。**
**条件 (a)（無料）は満たさない。** ただし必要額は **$200〜$350** で、
#1273 が «有料は規約で全滅» とした時点の見積り（数百万円規模）とは桁が違う。

### B-店 — いちばん効いた型

`site:instagram.com/p "<店名>" <市区町村>` を、**open data に Instagram を持たない店**
100 件（母集団 199,757 店）に投げた。

| | 値 |
| --- | ---: |
| 投稿が 1 本以上見つかった店 | **88 / 100 = 88.0%** |
| キャプションに店名が現れた店（機械判定） | 53 / 100 = 53.0% |
| **目視 15 件での precision** | **12 正 / 1 誤 / 2 曖昧 = 80.0%** |
| **補正後** | **42.4%** |
| **全国換算（1,177,934 店）** | **約 499,000 店** |
| 1 店あたりの投稿数 | 平均 6.99 本 |

**この型が強いのは «店が Instagram をやっている必要が無い» から**である。
Route A（店 → その店の公式アカウント）は店がアカウントを持っていないと成立しないが、
B-店は**誰の投稿でもよい**。

⚠️ **目視ラベルは [`out/store_posts_labels.json`](out/store_posts_labels.json) に判定理由つきで置いた。**
誤判定の温床は**短い一般名詞の店名**である（「ウイング」→ 就労支援事業所Wing が返った。
店名一致ありの 53 店のうち 10 店が 3 文字以下）。n=15 なので幅は広い（95%CI 概ね 55〜93%）。

### #1273 / #1284 の前提が 1 つ覆った

> Instagram Graph API(business_discovery, oEmbed)が App Review 必須で実機ブロック済み(OAuthException code 10)

**今回のトークン**（`instagram_basic` / `instagram_manage_insights` /
`pages_read_engagement` / `pages_show_list` / `business_management`）では
**第三者の飲食店アカウントに business_discovery が通り、`permalink` が返った。**

## 0.5 打開策の中身

### A. `business_discovery`（4.8 の再評価）

FSQ から取った実在の飲食店ハンドル 148 本に投げた結果:

| | 値 |
| --- | ---: |
| 解決 | **111 / 148 = 75.0%** |
| 未解決の理由 | 全件 `110 / 2207013 Invalid user id`（Business/Creator でない個人アカウント、または消滅） |
| 解決した店の投稿数合計 | 47,608 本 |
| **投稿数の中央値** | **276 本 / 店** |
| ページング可能 | 107 / 111 |
| **レート制限** | **200 コール/時**（`(#4) Application request limit reached`, `is_transient`） |

**投稿は余るほど取れる。足りないのは店の数だけ。**
ただし 200 コール/時では 50 万店に **2,500 時間**かかる。

### B. Web 検索でカテゴリ×地域から直接採る（4.11）

`site:instagram.com/p <カテゴリ> <地域>` を **#1273 §15 と同じ 108 セル**
（18 カテゴリ × 6 地域タイプ）で回した（324 credits）。

| | 値 |
| --- | ---: |
| 1 セル平均のユニーク投稿（3 ページ） | 25.0 本 |
| **タイトルに地名が現れる比率** | **58.6%** |
| **実効（対象地域）** | **16.5 本 / セル** |
| **«対象地域 5 本以上» を満たすセル** | **108 / 108** |

| tier | 地域一致率 | 地域タイプ | 地域一致率 |
| --- | ---: | --- | ---: |
| high | 66.4% | 超高密度都市 | 69.2% |
| mid | 61.1% | 大都市中心部 | 65.6% |
| tail | 48.4% | 大都市郊外 | 56.3% |
| | | 地方政令市 | 58.6% |
| | | 地方中核市 | 51.2% |
| | | 郊外 | 51.2% |

⚠️ **58.6% は «タイトルに地名が出るか» の近似である。** 手で中身を見ると
うなぎ×五所川原 6/10・ジンギスカン×高松 7/10・ラーメン×渋谷 8/10 に対し、
**ネパール料理×五所川原は 1/10** だった。最も弱いセルでも 5/28 は残る。

**深さ**: 1 セルを 10 ページまで送ると **64〜86 本**のユニーク投稿が取れ、
**10 ページ目でもまだ新規が 6〜8 本出る**。index はさらに深い。

**アカウント発見にも使える。** 正解が分かっている標本（FSQ が instagram 列を持つ店 100 件）で
測ったので目視ラベルは要らない:

| クエリの型 | top1 一致 | 上位のどれか一致 |
| --- | ---: | ---: |
| **`{店名} {市区町村} instagram`** | **79.0%** | **84.0%** |
| `{店名} {市区町村} site:instagram.com` | 53.3% | 56.7% |

open data に Instagram を持たない店 130 件（母集団 199,757 店）では
**86.9% で候補プロフィールが返る**。

### C. Common Crawl で店舗公式サイトを無料代替（4.14）

店舗公式サイト 60 ホストを cluster.idx で二分探索し、WARC レコードだけを range 取得した。

| | 値 |
| --- | ---: |
| Common Crawl に入っているホスト | **40 / 60 = 66.7%** |
| **Instagram リンクが取れたホスト** | **11 / 60 = 18.3%**（CC 内に限れば 27.5%） |

**4.3 の自前クロール（15.17%）と同等以上を、相手サーバに一切アクセスせず無料で得られる。**
n=60 なので幅は広い（±9.8pt）。1 件は `embed.js` の誤検出、ページ取得に失敗した
ホストがあるため過小評価側である。

一方 **媒体サイトからの埋め込み収集は不発**（14 ドメイン・222 ページで投稿 11 本 = 0.05 本/ページ）。
**抽出済みコーパスも使えない** — FineWeb-2 日本語は 20,000 文書に 1 本しか投稿 URL が残らない
（trafilatura が href を落とす）。**生 HTML でなければならない。**

## 0.6 規模と費用

### Route B（カテゴリ × 市区町村）で全国を張る

- 日本の市区町村 1,741 のうち飲食店が意味のある数ある自治体を約 800 と見て
  **800 × 132 カテゴリ = 105,600 セル**
- 1 セル 10 ページ = **1,056,000 クエリ** → Serper **$0.30/1,000 で約 $317**
- 歩留まり: 1 セル 70 本 × 地域一致 58.6% ≒ **41 本/セル** → **約 430 万本の投稿**

### Route A（店 → アカウント → 投稿）

- 1,177,934 店 × 1 クエリ = **約 $353**
- 候補が返る 86.9%、top1 一致 79.0%
- その後 `business_discovery` は **200 コール/時**がボトルネック（50 万店で 2,500 時間）

**Route B が量、Route A が精度。どちらも $200〜$350 の桁。**

### 規約とリスク（技術判断ではない）

| | |
| --- | --- |
| Instagram の robots.txt | **Googlebot / Bingbot は `/p/` を巡回してよい**。リスト外の我々は `User-agent: * Disallow: /` で**自前クロール不可**。検索経由でしか取れない |
| Serper | 結果の**保存・DB 化を禁じる条項が無い**。制限は «出典の詐称» と «付加価値の無いミラーリング» のみ。ただし実体は **Google SERP のスクレイピング**で、その規約リスクはこちらに残る |
| SerpApi | 同じ用途で **US Legal Shield 最大 $2M**。単価 $5.90/1,000 で **約 20 倍** |
| Brave | 「store, cache, or create a database of Search Results」を**明確に禁止**。使えない |
| Instagram の投稿 | 保存するのは `instagram_post_id` だけで表示は公式 Embed。#1342 §5② が «制約(c) と両立する» とした形と同じ |

## 4.2 Foursquare OS Places の `instagram`

### 仕様書の前提が古い — S3 は空、Hugging Face は gated

- S3 `s3://fsq-os-places-us-east-1/` に残っているのは `LICENSE.txt` と `NOTICE.txt` の **2 本だけ**
- Hugging Face `foursquare/fsq-os-places` は **gated**。無記名だと
  `HTTP 401` / `x-error-code: GatedRepo`
- ライセンスは **Apache-2.0 のまま**なので規約上は使える。**アカウントが要るだけ**である

オーナーからトークンを受け取り、release `dt=2026-08-11` の 100 parquet を全走査した。

### 実測（`out/fsq_instagram.json`）

| | 件数 | 割合 |
| --- | ---: | ---: |
| 日本の place | 5,017,666 | — |
| うち飲食（`Dining and Drinking` 配下） | 1,400,600 | — |
| うち閉店していない | **1,177,934** | 100% |
| **`instagram` 列を持つ店** | **57,897** | **4.92%** |
| **その異なりハンドル数** | **35,451** | — |
| 参考: `website` を持つ店 | 312,559 | 26.5% |

**Overture の 3.1 倍**（11,279 → 35,451）。**これが単一ソースとしては最大の供給源である。**

### Overture との重複

FSQ のハンドルから 300 本を無作為抽出（seed 20260828）して Overture 側と突き合わせた結果、
**72 / 300 = 24.0%** が Overture にも存在した。したがって

```
和集合 ≒ 35,451 + 11,279 − 0.24 × 35,451 ≒ 38,222 本
```

OSM 2,050・Wikidata 146 を足しても **約 40,000 本**である。

**判定: 供給は最大だが不足。** 57,897 店は 500,000 店の **11.6%**。

### 実務メモ

100 ファイルを一括 glob で読むと Hugging Face が **429** を返す（実測で 84 本目で停止）。
`fsq_instagram.py` は 1 ファイルずつ読み、失敗したら待って積み直す形にしてある。
parquet は国ごとに固まっているので、日本のレコードは特定のファイルに集中する。

## 4.11 保存権を明示した Web 検索 API — **本測定済み。§0.5 B / §0.6 が本体**

### まず、検索エンジンに Instagram の投稿ページは入っている

`instagram.com/robots.txt`（2026-08-28 取得）を読むと、**Googlebot と Bingbot は
`/p/` `/reel/` を巡回できる**。禁じられているのは `/*/c/` `/*/comments/` `/*/liked_by/`
と API 系のパスだけである。

```
User-agent: Googlebot
Disallow: /*/c/
Disallow: /*/comments/
Disallow: /*/liked_by/
Disallow: /accounts/login/*?next=
...
```

一方、**リストに無いエージェント（＝我々）は `User-agent: *  Disallow: /`** で全面禁止である。
自前クロールは不可、検索エンジン経由なら可、という構造になっている。

なお robots.txt は末尾で **Instagram 自身のサイトマップ**を公開している
（`ig_places_sitemap` / `ig_seo_profile_sitemap` / `ig_seo_location_sitemap` など）。
店の一覧としては理想的だが、**`*` の `Disallow: /` が掛かるので我々は取得できない。**
取得していない。

### 実際に検索して歩留まりを測った

`site:instagram.com/p <カテゴリ> <地域>` を 5 セル叩いた結果（各 10 件）:

| セル | 投稿 URL | 対象地域の店名が読み取れたもの |
| --- | ---: | ---: |
| 焼き鳥 × 東京 | 10 / 10 | 約 6 |
| ラーメン × 青森 | 10 / 10 | 約 6 |
| ラーメン × 高松 | 10 / 10 | 約 5 |
| 寿司 × 高松 | 10 / 10 | 約 6 |
| **うなぎ × 高松** | 9 / 10 | **1** |

**平均 約 4.8 店 / クエリ。** タイトルにキャプションが入るので、
**店名がそのまま読める**（例: 焼鳥 鍈輝 / 焼き鳥 足るを知る / 小江戸鳥や / 麺道 一休 /
横浜家系ラーメン 高松家 / 寿司濱野 / 寿し勝 / 鰻松）。

**うなぎ × 高松だけが 1/10 に落ちる。** これは経路の失敗ではなく、
そのセルに店自体が少ないという #1273 §32 の «restaurant shortage» である。
**カテゴリ × 地域のセルごとに測り直す必要がある**（108 セルの本測定は未実施）。

### 保存権 — ベンダによって条文が正反対だった

| ベンダ | 無料枠 | 単価 | 結果の保存・DB 化 |
| --- | --- | --- | --- |
| **Brave Search API** | $5/月クレジット ＝ 約 1,000 req | $5 / 1,000 | **明確に禁止**。「store, cache, or create a database of Search Results, in whole or in part, other than transient storage required for operation of Customer Applications」。**プラン別の例外は規約本文に無い** |
| **Serper** | **2,500 クエリ（カード不要）** | **$0.30〜/1,000** | **禁止条項が無い**。制限は «出典の詐称» と «付加価値の無いミラーリング» のみ |
| SerpApi | 250 検索/月 | $5.90 / 1,000（$1,475/月 25万） | 保存に関する条項は無い。代わりに **US Legal Shield 最大 $2M** を提供 |
| Google Custom Search JSON | 100 クエリ/日 | $5 / 1,000 | **新規受付終了**。既存顧客も 2027-01-01 までに移行 |
| Bing Search APIs | — | — | **2025-08-11 終了済み** |
| DataForSEO | — | 最低入金 $50 | 保存条項はページ上に記載なし |

**Brave と Serper で条文が正反対である。** 仕様書は Brave を前提に「標準プランのまま
検索結果 DB を作らない」としているが、**その判断は Brave 固有**であり、
Serper には当てはまらない。

### 規模と費用

500,000 店 ÷ 4.8 店/クエリ ＝ **約 104,000 クエリ**（重複ゼロの理想値）。
重複を 2 倍と見て **約 200,000 クエリ**。

| | 費用 |
| --- | ---: |
| Serper（$0.30〜$1.00 / 1,000） | **$60 〜 $200** |
| SerpApi（$5.90 / 1,000） | 約 $1,180 |
| Brave（$5 / 1,000） | 約 $1,000（**ただし保存禁止**） |
| 無料枠だけ（Serper 2,500 + SerpApi 250/月 + Brave 1,000/月） | **約 1〜6 年** |

**(a) 無料は満たさない。ただし 108 セルの本 PoC（約 1,000〜2,000 クエリ）は
Serper の無料枠 2,500 に収まるので、PoC 自体は無料でできる。**

**判定: 採用候補。** 108 セルの本測定と深度・クエリ型のチューニング結果は §0.5 B、
規模と費用は §0.6 にある。

## 4.14 Common Crawl の外部ページ外向きリンク

最新 crawl `CC-MAIN-2026-34` の URL index を実測した（`cc_instagram_index.py`）。

| | 件数 |
| --- | ---: |
| cluster.idx の行数 | 873,102 |
| **instagram.com の cdx レコード** | **78** |
| うち robots.txt | **77** |
| **投稿 URL（`/p/`・`/reel/`）** | **0** |

Instagram は robots.txt で `*` を拒否しているので、**Common Crawl に投稿 URL は存在しない**。
仕様書が言うとおり経路は「他サイトの外向きリンク（WAT）」だけだが、その規模は

- WAT ファイル **100,000 本** × 約 **151 MB** ＝ **1 crawl あたり約 15.1 TB**

ここまでが一度目の測定である。**そのあと打開策が見つかった** → §0.5 C。

仕様書の「既知の公式サイトドメインに限定せよ」を素直にやると、
**店舗公式サイトの生 HTML を無料で・相手サーバに触れずに読める**。
60 ホストで 18.3% から Instagram リンクが取れ、4.3 の自前クロール（15.17%）と同等以上だった。

**判定: 打開策あり（§0.5 C）。全走査は却下、対象限定の range 取得は採用候補。**
