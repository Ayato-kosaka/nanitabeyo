## 判定
- hypothesisの中核(数百クエリ規模の連続実行でも429/CAPTCHA/ブロック兆候ゼロ)は**実測で支持された**。既存REPORT.mdの10件確認を24.5倍の規模(245クエリ、delay0秒〜1秒、並列1〜10)に拡張しても劣化の明確な兆候（エラー・ブロック文言）は一切出なかった。
- ただし軽微な劣化シグナルが1つ見られた: 逐次delay0のフェーズAで前半50件平均3.00s→後半50件平均3.79s(+26%)とわずかに遅くなる傾向があった。これはブロックではなく単なるレイテンシ変動(YouTube側の負荷分散/このマシンのネットワーク揺らぎ等)の可能性が高いが、"崩れない"と言い切るには数千クエリ規模でのより長時間の検証が望ましい。
- 並列度10(F_par_conc10)はn=20と少数サンプルのため参考値に留まるが、スループット上限を探る兆候(失敗率上昇)はこの範囲では見られなかった。
- スケール試算: 実測の逐次delay0スループット(約1,060 q/h、3.4s/query)をそのまま延長すると、134カテゴリ×55エリア=7,370クエリの全国1回掃引は約7時間で完走できる計算になる。並列5(約3,900 q/h)なら約1.9時間、並列10(参考値、約11,700 q/h)なら1時間未満という試算になり、いずれも公式YouTube Data API v3の無料枠(10,000 units/日、search.list 1回100 units≒1日100回≒0.73日分カバーで7,370クエリには74日分の枠が必要)とは桁違いに有利。ただし本検証は「技術的にブロックされずに実行できる」ことの実測に留まり、YouTube利用規約上の非公式スクレイピング(yt-dlp)の許容性・法務適合性は別問題として未確定のままである(既存結論を変更しない)。

## 次のアクション(人間向け)
1. 本検証は最大245クエリ・約17分の実行に留まる。数千クエリ規模・数時間にわたる長時間試験(特にフェーズAで見えた後半の軽微な遅延傾向がさらに悪化しないか)は未実施のため、本番導入前に追加の長時間耐久試験を推奨する。
2. IPアドレス単位のブロックである可能性が高く、本検証は単一サンドボックスIPからの実行結果に過ぎない。本番運用時の実IP(クラウドVM等)でも同様の耐性があるかは別途要確認。
3. 技術的な実行可能性が高いと分かった一方、yt-dlpによるYouTube検索スクレイピングがYouTube利用規約上グレーであるという既存の結論(REPORT.md)は変わらないため、本番採用の可否は法務確認が前提。
