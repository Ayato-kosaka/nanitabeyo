# idea検証: prefecture-x-134category-real-pilot-sweep

**title**: 実データ都道府県×134カテゴリ パイロットスイープ(hit-rate/地域関連性の実測)
**検証日**: 2026-08-13
**検証方法**: 実機DB(`dev.dish_category_features`)から134gateカテゴリのmarket_salienceスコアを取得し、
高/中/低salience各6カテゴリ×47都道府県=846クエリを構築、`/tmp/yt-dlp-latest`(2026.07.04版)を
Python 3.11.15経由で `ytsearch5:` 形式で並列5実行し、全846クエリの動画タイトルを実測。
**判定**: **hypothesisの中核(0件ヒット率の急増・地域関連性の低さ)は実測で明確に反証された** —
846/846クエリで0件ヒットなし、都道府県名のタイトル一致率は93.3%(単純部分文字列一致のみ、
英語表記や市区町村名での言及は未カウントのためこれは下限値)。

## 実施内容と生の結果

### 1. DBからの134カテゴリ salienceデータ取得

```sql
select dcf.dish_category_id, coalesce(dc.labels->>'ja', dc.label_en), dcf.score
from dish_category_features dcf
join dish_categories dc on dc.id = dcf.dish_category_id
where dcf.feature_type = 'market_salience' and dcf.feature_key = 'region:country:JP'
  and dcf.dish_category_id in (
    select dish_category_id from dish_category_features where feature_type='gate' and score=1
  )
order by dcf.score desc;
```

134行取得を確認(`salience_134.csv`)。上位6件は寿司・うどん・ラーメン・焼き鳥・ピザ・パスタ(score 0.97-0.98)、
中位6件はカレーうどん・懐石料理・牡蠣料理・天津飯・油淋鶏・エビチリ(score 0.70-0.72)、下位6件は
アクアパッツア・四川料理・プリンアラモード・韓国料理・居酒屋・トースト(score 0.42)。

※テストプランのSQLでは `dc.ja_label` という列を指定していたが、実際のスキーマには存在せず
(`dish_categories`テーブルの実列は `label_en`, `labels`(jsonb多言語辞書))、`labels->>'ja'` に修正して実行した。

### 2. 846クエリの構築

高/中/低salience各6カテゴリ×47都道府県=846クエリを生成し、`846 queries written` を確認
(`pilot_846_queries.tsv`)。

### 3. yt-dlp実行 — 実行時トラブルと修正

**1回目の実行は846/846件が即座に失敗した**(所要15秒で完了という明らかな異常値)。原因を調査したところ、
`subprocess.run(['/tmp/yt-dlp-latest', ...])` のように standalone zipapp を直接実行すると、
shebang(`#!/usr/bin/env python3`)が指すシステムのデフォルトPython(`Python 3.7.3`)が使われてしまい、
`ImportError: You are using an unsupported version of Python. Only Python versions 3.10 and above are
supported by yt-dlp` で即座に失敗していた(returncode=1が846件全て)。単発の動作確認コマンド
(`$PY /tmp/yt-dlp-latest "ytsearch3:..."`のように明示的にPython 3.11を第一引数として渡す形)では
成功していたため、この形式(`[PY311, YTDLP, ...]`)に実行スクリプトを修正して再実行し、正しい結果を得た。
(Round 1のログでもこのPython 3.11 standalone実行体を使っていたはずだが、今回のPoCスクリプトでの
実装ミスとして記録しておく。)

**2回目(修正後)の実行結果**:
```
todo=846
...
DONE total_elapsed=808s
```
846/846クエリ完走、**エラー(returncode≠0)は0件**、429/CAPTCHA/"not a bot"/レート制限系のブロック兆候も
stderr全件を走査して**0件**。並列5・846クエリ・808秒(約13.5分)で完走 = 実測スループット約3,769クエリ/時
(Round 1の並列5実測値 約3,900〜5,000クエリ/時とほぼ整合)。

#### pref_in_title=Falseだったケースの内訳確認(93.3%が下限値であることの裏付け)

「都道府県名がタイトルに一致しない」判定になった6.7%(57/846件)を精査すると、その多くは**英語圏向け
タイトル(ローマ字県名・都市名)や市区町村名での言及**であり、実際には地域関連性がある(=単純な部分
文字列一致という判定ロジックの限界による偽陰性):
```
寿司 岩手県 -> "[Iwate, Morioka, Miyako] Featured Sushi Restaurants -Lunch Edition-"
うどん 山形県 -> "Yamagata's local dish, \"Hippari Udon,\" bursting with flavor"
ラーメン 富山県 -> "[2026 Latest] Toyama Prefecture Ramen Ranking TOP 20!"
カレーうどん 北海道 -> "【札幌グルメ】カレーうどんが超おいしいお店...A famous curry udon restaurant in Sapporo"
```
これらはいずれも判定ロジック上は「不一致」だが目視では明確に地域関連性がある。つまり実際の地域関連性は
93.3%よりさらに高い。

#### コンテンツの多様性(同一動画の使い回しでないことの確認)

846クエリ×5件=4,230件のタイトルスロットのうち、ユニークタイトル数は3,901件(重複率7.8%)。
同一カテゴリ内で都道府県を変えても大半のケースで異なる動画が返っており、YouTube側が単純に
「全国共通の人気動画」を都道府県名クエリに関係なく使い回しているわけではないことを確認した
(例外: 「うどん 香川県」で複数の都道府県クエリに同じ有名動画が重複ヒットするケースはあったが、
846件中2タイトルのみで軽微)。

#### スケール外挿

- 実測: 846クエリ / 808秒(並列5) = 約3,769クエリ/時
- 本番規模(47都道府県×134カテゴリ=6,298クエリ)への外挿: 6,298 / 846 × 808秒 ≈ 6,015秒 ≈ **約100分(約1.67時間)**
- これはRound 1のytdlp-youtube-search-endurance-limits.mdでの試算(並列5で約1.9時間)とほぼ整合し、
  むしろ実測ベースでやや短い結果になった(846クエリという規模でのより安定したサンプルのため)。

## 判定(test_planの判定基準に対して)

1. **zero_hit_rateがlow salience×一部県で顕著に高い(例30%超)か** → **NO、明確に反証**。
   846クエリ全件で0件ヒットは1件もなく、low salienceのみに絞っても0.0%。当初の「ロングテールカテゴリ×
   小規模県で急増するはず」という仮説は、少なくとも`ytsearch5`(上位5件取得)という設定においては
   まったく成立しなかった。ただしこれは「上位5件が確実に見つかる」ことの実証であり、「その5件が
   実際にnanitabeyoのdish_media品質基準(embeddable・料理が写っている等)を満たすか」「6件目以降にも
   十分な供給があるか」までは検証範囲外(video_countが`ytsearch5`の上限に常に張り付いており、真の
   供給量[5件超かどうか]は今回の設計では測れていない、という限界がある)。
2. **pref_in_title_rateが低い(例20%未満)か** → **NO、明確に反証**。全体93.3%、47都道府県すべてで
   70%を上回り、しかも上記の通り実際の関連性はロジック上の偽陰性(英語表記・市区町村名)を補正すれば
   さらに高いと推定される。「沖縄県 エスカルゴ」のような無関係動画の氾濫という当初の懸念は、
   少なくとも134カテゴリ×47都道府県の実データでは支持されなかった。都道府県名を検索クエリに含める
   設計はRoute Bの地理的関連性シグナルとして明確に機能している。
3. **salienceスコアと実際のヒット件数の相関** → **測定不能(設計上の限界)**。`ytsearch5`固定のため
   video_countは846件全てで5.00に飽和しており、salienceとの相関を件数ベースでは算出できなかった。
   代替指標として関連性(pref_in_title_rate)をtier別に見ると high 98.2% > low 91.8% > mid 89.7%と
   わずかな差はあるが単調な相関はなく、salienceスコアが低いからといって地域関連性が大きく劣化する
   様子は見られなかった。

## 結論と次のアクション(人間向け)

- **当初hypothesisの核心的懸念(ロングテール×小規模県での0件ヒット急増、地域関連性の低さ)は実測で
  反証された**。むしろ846クエリという広いカバレッジでも「都道府県名+料理名」という単純なRoute B
  クエリ設計は高いhit-rateと高い地域関連性を両立していた。フルスイープ(6,298クエリ)への設計変更
  (都道府県名抜きの全国クエリ+後段フィルタへの切り替え等)は不要と判断できる材料が得られた。
- **残された未検証事項**: (a) `ytsearch5`上限に常に張り付いていたため、真の供給枯渇ライン(6件目以降が
  実在するか)は未測定。dish_media候補を複数件確保したい場合は`ytsearch10`や`ytsearch20`での再測定が
  望ましい。(b) タイトルの地域名一致は「地域関連性」の代理指標に過ぎず、実際に動画内で料理カットが
  映っているか(embeddable品質)は本検証の範囲外(Round 1のREPORT.mdで別途20サンプルの歩留まり測定
  [4/20=20%]を実施済み、本検証と合わせて解釈する必要がある)。(c) 全846件のタイトルのみ保存し
  動画IDは保存していないため、重複排除・embeddable判定などの後段処理を正確に行うには再度動画IDを
  含めた形での本番実行が必要。
- **フルスイープのスケジューリング設計への示唆**: 6,298クエリの外挿所要時間は並列5で約100分
  (1.67時間)。1日1回のバッチとして十分現実的な規模であり、複数日への分割は不要と判断できる。
