# なに食べよ — プロダクト定義

**何の文書か**: このプロダクトが «何で、誰の、どの瞬間の、何を解き、誰の財布でどう稼ぐか» の正本。機能を足す・削る判断はここに照らす。
**読者**: オーナー、開発チーム（Claude Code 含む）、投資家に説明する前の自分。
**更新規則**: ここには **オーナーと合意した、変わらない定義だけ** を書く。実測・市場の数字・競合の動きは毎月変わるので [#234 投資家向けピッチ](https://github.com/Ayato-kosaka/nanitabeyo/issues/234) に置き、検討の経緯は [#1406](https://github.com/Ayato-kosaka/nanitabeyo/issues/1406) に置く。覆ったらその場で書き換える（合意日: 2026-09-03 / 09-09）。

## 一文で

> **比べる前に、今日の店が決まるアプリ。**

現在地・時間帯・誰と・気分をタップ → 料理カードを 1 つ選ぶ → その料理の写真付きの近くの店が出て、地図で行く。

## コア価値

> **速くて、納得できて、迷わない。** 選択疲れのない店決め。

手段は 2 つで、順序がある。

1. **自由入力ではなく、固定された «迷わない選択肢» から料理を先に提案し、それから店を提案する。**
   「気分は？」の自由入力はユーザーを迷わせるので採らない。
2. **Instagram 的なビジュアルで「行きたい」を作り、口コミ・価格帯で「大丈夫」を添えて、比較せずに納得して終わらせる。**

Google マップ（Gemini「マップに相談」）やぐるなび UMAME! の「気分を自由入力 → 店」とは構造が違う。差別化はこの順序と選択肢の設計にある。

## コアペルソナ

> **なに食べたいか決まっていないまま、友人・恋人との店決めを任される 20 代の社会人。**

- 今は Instagram / TikTok の保存 → Google マップで場所・価格・口コミを確認 → LINE で送る、と 3 つを行き来して候補を作る。**候補を作るところが一番重い。**
- 一人で決める日も、同じ人の別のシーンとして扱う。**別ペルソナを作らない。**
- 属性（年齢・職業）は仮置き。**需要の理由はまだ 1 人からも聞いていない**（下記「未検証」）。

## 入口とコアを分ける

|                                    | 対象                         | 目的                                   |
| ---------------------------------- | ---------------------------- | -------------------------------------- |
| 入口（ショート動画）               | 「今日なに食べよ」と思う全員 | 広い共感でインストールさせる。狭めない |
| コア（プロダクトが最適化する相手） | 上のペルソナ 1 人            | 継続利用する最初の 1,000 人。狭くする  |

動画の反応でプロダクトを設計しない。

## 事業の形

**誰の財布か**: 飲食店が今、インフルエンサーに「自分の店のショート動画を作って流してもらう」ために相対・不透明に払っている金（無料招待、PR 案件、動画代行）。露出課金（食べログ PR 等）の財布ではない。

**何を売るか**: 店が買うのは露出ではなく **«自分の店について投稿してくれる人の関心»**。

| 要素       | 決めたこと                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 店の支払い | 広告原資を都度購入（最低 1,000 円）。額は周囲の店との相対で決まるオークション型。多く出すほど、その店に投稿したい人が増える                                    |
| 分配       | 原資の 70% を、**その店への来店につながった投稿** をした人に配る。30% が当社（詳細は [#811](https://github.com/Ayato-kosaka/nanitabeyo/issues/811)）           |
| 順位       | **金で買えない。** 表示順はフラットで、正直な投稿・伸びる投稿が上に来る。悪い感想も消さない                                                                    |
| 成果の単位 | **アプリ内で測れる来店の代理指標だけ**（投稿数・アプリ内表示・地図ピン。将来は予約）。TikTok 等での再生は売りにも分配の根拠にもしない                          |
| PR 表示    | 分配対象の店への投稿には、**プラットフォームが自動で PR 表示を付ける**（景品表示法のステマ規制に沿う）                                                         |
| 三者の順序 | **ユーザー → 店（1 エリア） → 投稿者**。ユーザーと «決まった» の計測を先に持ち、それを店に見せて原資を集め、原資で投稿者を呼ぶ。報酬の原資を自己資金で埋めない |

消費者アプリは «決める» 道具であると同時に、**店にとっての来店の計測装置** である。成果で払えるのは、決める瞬間を握っている側だけ。

## 最小のくさび（最優先の穴）

> **選んだ料理の店が、必ず、近くに出る。**

これが成立するまで「アプリを開く後押し」の機能も、店への営業も効果を測れない。順序を守る。

## やらないこと

- 気分・要望の自由入力
- 候補・情報・選択肢を増やして比較させる設計（星評価の一覧、口コミ件数の比較）
- 金で表示順を売ること
- 新店探索メディア、店のコレクション、クーポン探しアプリになること

## 未検証（正本に書けないもの）

- **需要の理由**: 行動の証拠はある（数字は #234）が、なぜ戻ってくるかを聞いた人が 0。最初の宿題は、ペルソナに該当する身近な 1 人に黙って使ってもらい、驚いたことを Issue に書くこと
- ペルソナの属性（20 代・社会人）と、週の店決め頻度
- 店が払う単価と、1 エリアで三者が回る密度

## 機能を考えるときの判定

新しい機能案は、次の 3 問すべてに「はい」でなければ着手しない。

1. コアペルソナが «任されて候補を作る» 瞬間を速くするか、納得を上げるか（→ コアペルソナ）
2. 選択肢・情報・比較を増やさないか。表示順を金で売らないか（→ コア価値・やらないこと）
3. 「店が必ず出る」より先にやる理由を言えるか（→ 最小のくさび）
