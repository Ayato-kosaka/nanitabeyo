# なに食べよ — プロダクト定義（ペルソナ / コア価値 / 現在地）

**何の文書か**: このプロダクトが «誰の、どの瞬間の、何を» 解くのかの正本。機能を足す・削る判断はすべてここに照らす。
**読者**: オーナー、開発チーム（Claude Code 含む）、投資家に説明する前の自分。
**更新規則**: 数字は BigQuery 実測（取得日を併記）。仮説と事実を混ぜない。覆ったら書き換える（経緯は [#1406](https://github.com/Ayato-kosaka/nanitabeyo/issues/1406) へ）。

---

## 0. 一文で

> **「なに食べよ」は、外食の «決める» を 30 秒で終わらせるアプリ。**
> 食べログ・Google マップ・Instagram は «探す / 比べる / 確かめる» の道具であって、«決める» 道具ではない。

- コア価値: **世界で一番早く、納得して店が決まる。**
- なぜ早いか: 「行きたい（体験想像）」と「大丈夫（安心確認）」を 1 本の短い導線に圧縮し、**比較させずに終わらせる**から。
- やらないこと: 店の網羅・星評価の比較・新店開拓メディア・クーポン探しアプリになること。

## 1. 現在地（BigQuery 実測 2026-09-02、`food-scroll.nanitabeyo_logs_prod.frontend_event_logs`、広告費ほぼゼロ・ショート動画のみ）

### 1-1. 規模と定着

| 指標                                                    |                   値 | 読み方                                                                                                                                      |
| ------------------------------------------------------- | -------------------: | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 直近 30 日のユニークユーザー（匿名端末単位）            |                9,153 | 全員がショート動画経由                                                                                                                      |
| 直近 8 週で **3 週以上** 戻ってきた人                   |                2,369 | 「習慣の芽」。うち 5 週以上は 279 人                                                                                                        |
| 直近フル週（8/24 週）の WAU / うち 8 日以上前からの復帰 | 2,068 / 1,713（83%） | 週の大半は新規ではなく復帰                                                                                                                  |
| 初回から 1〜7 日以内に戻る率（5〜7 月コホート）         |              28〜38% | 検索した人に限ると 33〜38%                                                                                                                  |
| 初回から 28〜41 日後に戻る率（5〜6 月コホート、全員）   |              17〜18% | [#234](https://github.com/Ayato-kosaka/nanitabeyo/issues/234) の目標 D30 ≥ 10% は超えている。初回に検索した人だけなら 28〜55 日窓で 28〜31% |
| 開いた週に、開いた日数                                  |       約 1.2 日 / 週 | 週 1 回「決めて閉じる」道具。毎日開く習慣にはなっていない                                                                                   |

### 1-2. ファネル（直近 30 日、ユーザー単位）

```
9,153 起動 ─→ 6,614 検索した(72%) ─→ 5,397 料理を選んだ(59%)
                                        ├─→ 2,873 アプリ内で店を見た(31%) ─→ 1,112 地図ピンを開いた(12%)
                                        └─→ 4,265 「候補なし」で Google マップ退避を提示(47%) ─→ 3,984 が Google マップを開いた
                                              うち 2,521 人は店を 1 軒も見ずに退避だけ
保存 / いいね / 共有 まで到達: 267 人 (2.9%)
```

**核心の事実**: 料理を選んだ人の **47% に、その料理の店を出せていない。** «店が決まる» を約束して、半分は Google マップに決めてもらっている。
それでも退避組の 28% が翌週以降も戻ってくる（店まで見た組は 36%）。つまり **料理提案だけで価値が成立している**が、店が出れば定着は約 1.3 倍になる。

### 1-3. 誰が使っているか

| 切り口                     | 実測（検索したユーザーの分布）                                          | 示唆                                                       |
| -------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------- |
| 誰と（初回検索の `scene`） | 一人 37% / 友人 23% / デート 23% / 家族 12% / 飲み会 3%                 | **一人が単独最大**。「誰かと」合計で 50%                   |
| シーン別の 1〜7 日再訪率   | 一人 34 / 友人 37 / デート 38 / 家族 33 / 飲み会 34%                    | **差が無い**。ペルソナを «誰と» で切っても定着は変わらない |
| 時間帯                     | 夕食 64% / 昼食 50% / 深夜 12% / 朝 7%（重複あり）                      | 夕食が主戦場                                               |
| 距離                       | **91% が既定の 500m のまま**                                            | «今ここ» で決めている。移動して行く店探しではない          |
| 地域                       | 東京 23% / 大阪 9% / 神奈川 8% / 愛知 7% / 埼玉・兵庫・福岡・千葉 4〜5% | 首都圏に寄るが全国に散っている                             |
| 初回に検索しなかった人     | 14%（再訪 5%）                                                          | 検索に至れば定着し、至らなければ二度と来ない               |

## 2. VC の 6 つの問いに、いま答えられること（gstack `/office-hours` の強制質問を投資家の質問として使う）

| #   | 問い                                     | いまの答え                                                                                                                                 | 正直な評価                                                                                              |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 1   | **需要は実在するか**（興味ではなく行動） | 無広告で月 9 千人が使い、2.4 千人が 8 週中 3 週以上戻る。検索完了 72%                                                                      | 行動はある。**「無くなったら困る」の証拠（課金・インタビュー・苦情）はゼロ**                            |
| 2   | **今の代替手段は何か**（真の競合）       | Instagram / TikTok で「行きたい」→ Google マップで「大丈夫」→ LINE で「ここでいい？」の 3 アプリ跨ぎ                                       | 代替は「無い」ではなく「面倒」。94% が店選びに迷った経験、52.6% が「情報が多すぎる」（Bitee 調査 2026） |
| 3   | **その人は誰か**（カテゴリではなく人）   | §3 のペルソナ                                                                                                                              | 属性は仮説。データが言えるのは «誰と» ではなく «週に何回、今ここで決めるか» が効くこと                  |
| 4   | **最小のくさびは何か**                   | **選んだ料理の店が、必ず、近くに出ること**。これが無いと 47% を Google マップに渡す                                                        | 機能追加より先に埋めるべき穴。ここが埋まるまで「後押し」機能を積んでも漏れる                            |
| 5   | **観察して何に驚いたか**                 | (a) 一人利用が最大 (b) 店が出なくても 28% 戻る (c) 距離を誰も触らない (d) 保存・共有は 3% しか使わない                                     | 「料理を決める」瞬間に価値があり、「店を保管する」価値はほぼ無い                                        |
| 6   | **3 年後に必須になるか**                 | Google マップ Gemini「マップに相談」（2026-08 国内提供）、ぐるなび UMAME!（2026-06 気分提案）、Bitee（2026-07 PoC）が同じ「気分→店」に来た | **「気分→店」は 1 年で汎用機能になる。** 残る差は §4 の 3 つだけ                                        |

## 3. コアペルソナ（正本）

### 3-1. マーケティングの入口と、プロダクトのコアを分ける

|                                        | 対象                         | 目的                                         |
| -------------------------------------- | ---------------------------- | -------------------------------------------- |
| **入口（ショート動画）**               | 「今日なに食べよ」と思う全員 | 広い共感でインストールさせる。ここは狭めない |
| **コア（プロダクトが最適化する相手）** | 下記 1 人                    | 継続利用する最初の 1,000 人。ここは狭くする  |

この 2 つを混同しない。動画の反応でプロダクトを設計しない。

### 3-2. ペルソナ: 「ユイ」（オーナー定義 2026-08-26 を、実測で補正）

| 項目                 | 内容                                                                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 属性                 | 20〜28 歳の社会人。都市部在住・通勤。外食は週 2〜4 回                                                                                                                         |
| 決める瞬間           | **「なに食べたいか決まっていない」まま、今いる場所の 500m 圏で、夕食を決める**。一人の日も、友人・恋人と一緒の日もある（**シーンは同じ 1 人の中にある**。別ペルソナにしない） |
| 今の行動             | Instagram / TikTok で見て「行きたい」→ Google マップで価格帯・口コミを見て「大丈夫」→ 誰かと一緒なら LINE で合意。**アプリの行き来と比較に疲れている**                        |
| 痛み                 | 情報が足りないことではなく、**候補が多すぎて決めるのが面倒**。「最高の店」ではなく「失敗しない店に早く決めたい」                                                              |
| 成功の定義           | 開いてから **30 秒で「ここにしよう」と言えて、行った結果に納得できる**                                                                                                        |
| 使わない理由（現状） | 「結局いつもの店・チェーンでいい」— 現状で大きく困っていないので、**起動する理由が弱い**                                                                                      |

### 3-3. コアではない人（入口としては受けるが、設計の主語にしない）

- **新店開拓が趣味の人**: 熱量は高いが「探す」が目的。比較を楽しむので、比較を消す設計と衝突する
- **旅行者・遠征者**: 距離を広げて探す。500m 圏の «今ここ» とは別の問題
- **店の記録・コレクションをしたい人**: 保存 / 共有の到達率 3% が示す通り、今のユーザーはほぼ求めていない

### 3-4. 実測がペルソナ仮説に言っていること

1. 「一人より誰かと」の方が定着する、は**支持されない**（シーン別再訪率に差なし）。ペルソナの主語は «誰と» ではなく **«決める頻度 × 決定疲れ»** に置く
2. 「20〜28 歳」は未検証。ログに年齢は無い。**インタビューでしか埋まらない**（§6）
3. 「今ここ・500m・夕食」は強く支持される。ペルソナの行動記述はこれに合わせた

## 4. なぜ Google / ぐるなびではなく我々か（VC が必ず突く）

「気分から店を提案する」は 2026 年中に Google マップ（Gemini）・ぐるなび（UMAME!）・新興（Bitee）が全員やる。**提案 UI そのものは差別化にならない。** 残る差は次の 3 つで、いずれも「決める」に特化しているから積める資産である。

| 資産                                  | 何か                                                                                                                                                                                                                | 彼らが持ちにくい理由                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **料理カテゴリ × 状況の特徴量グラフ** | 料理カテゴリごとの dining_pace / timeSlot / scene / satiety 等のスコア（`dish_category_features`。補正の運用は [`.claude/skills/dish-feature-correction/`](../../.claude/skills/dish-feature-correction/SKILL.md)） | 彼らの主語は「店」。我々は「料理 → 店」の順で決めさせるので、料理側の構造データが溜まる  |
| **«決めた»後の行動ログ**              | 提案 → 料理選択 → 店 → 地図ピン → （来店）の 1 本の系列（[`docs/specs/behavior-tracking-logs.md`](../specs/behavior-tracking-logs.md)）                                                                             | 店一覧を見せる UI では「どれに決めたか」が取れない。我々は 1 件ずつ見せるので取れる      |
| **店舗 → 投稿者への成果分配**         | 店の広告費を、来店に効いた投稿へ配る（[#811](https://github.com/Ayato-kosaka/nanitabeyo/issues/811)）                                                                                                               | 露出課金（食べログ PR / ホットペッパー順位連動）を主収益にする側は、自社モデルと食い合う |

**正直な弱点**: 3 つとも「積めば差になる」段階で、まだ差になっていない。Google マップが「30 秒で 1 軒だけ提案」を出したら、今の UI の優位は消える。守れるのは (2) と (3) で、その両方とも **供給（店が出ること）が前提**である。

## 5. 収益モデル（現時点の方針）

| フェーズ               | モデル                                                                                                                                 | 条件                                                                          |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 最終形                 | 店舗が広告原資を都度購入 → 70% を来店に効いた投稿者へ分配、30% が当社（[#811](https://github.com/Ayato-kosaka/nanitabeyo/issues/811)） | 店舗数・投稿者数・来店計測が揃ってから                                        |
| 初期（#1406 で検討中） | 候補: 予約送客アフィリエイト / 店舗特典と送客の組合せ / 特典提供を条件にした無料掲載                                                   | **「起動理由を強めながら収益化できるか」で選ぶ。** 収益額の最大化では選ばない |

初期モデルの選定はまだオーナー判断待ち（§7）。

## 6. 未検証の仮説と、検証方法

| 仮説                               | 今の根拠                             | 検証方法                                                           | 判定基準                                          |
| ---------------------------------- | ------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------- |
| H1. コアは 20〜28 歳の社会人       | オーナーの観察のみ                   | 実ユーザー 10 名にインタビュー（年齢・週の店決め回数・今使う手段） | 10 名中 6 名以上が週 2 回以上「決める」機会を持つ |
| H2. 店が出れば定着が上がる         | 店を見た組 36% vs 退避組 28%（相関） | 供給を埋めた地域で、退避率と 1〜7 日再訪を前後比較                 | 退避率 47% → 20% 以下で再訪率が +5pt 以上         |
| H3. 料理提案だけで価値がある       | 退避組・結果なし組でも 28〜46% 戻る  | インタビューで「店が出なかったのに、なぜ戻ったか」を聞く           | 「なに食べたいかが決まるから」が主回答            |
| H4. 「開く理由」は機能ではなく想起 | 開いた週でも 1.2 日 / 週             | 検索時刻の分布と、通知 / ウィジェット等の想起施策の A/B            | 週次起動回数が 1 → 1.5                            |
| H5. 保存・共有は不要               | 到達率 3%                            | 消しても再訪が下がらないか                                         | 再訪率が変わらなければ導線を畳む                  |

## 7. オーナー判断待ち

[#1406 の未解決事項コメント](https://github.com/Ayato-kosaka/nanitabeyo/issues/1406) が正。ここには要点だけ置く。

1. ペルソナの主語を «誰と» から «決める頻度 × 決定疲れ» に置き換えること（§3-4）
2. 機能検討の前に「選んだ料理の店が必ず出る」を最優先の穴と認めること（§2 の問 4）
3. 初期収益化で最初に試す 1 案（§5）

## 8. 機能を考えるときの判定（次の工程への橋）

新しい機能案は、次の 3 問すべてに「はい」でなければ着手しない。

1. **ユイが «今ここで夕食を決める» 30 秒を短くするか、納得を上げるか**（どちらでもないなら、それは別プロダクトの機能）
2. **§1-2 のファネルのどの数字を動かすか、事前に 1 つ言えるか**（言えないものは計測できない）
3. **比較を増やさないか**（候補・情報・選択肢を増やす機能は、原則としてコア価値と逆行する）
