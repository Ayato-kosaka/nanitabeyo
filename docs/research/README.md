## 経営・開発上の結論

### 1. 競合は一つの検索サービスではなく、分断された行動の束

飲食意思決定は、SNS での偶発的な発見、検索・地図での条件確認、口コミでの不安解消、同行者との合意、予約、来店後の保存・共有に分かれる。若年層の発見では Instagram や TikTok が強い一方、最終確認では Google、Google マップ、グルメサイト、公式情報が併用される（JP-001〜008、JP-018〜026、GL-001〜008）。したがって「検索媒体のシェア」だけで勝敗を定義しない。

「なに食べよ」が解くべき仕事は、既知の店名を最短で引くことより、曖昧な気分から食べたい料理に気づき、現実に行ける店へ短時間で収束させること。その後の正確な店舗確認と予約・地図への移動までを一つの意思決定として測る。

### 2. 料理写真は入口として有力だが、写真だけでは決まらない

料理の見た目、店内の雰囲気、量、メニューは探索と期待形成に効く（JP-001、JP-002、JP-008、JP-009、AC-004〜007）。一方、実際の候補絞り込みでは価格、場所、営業時間、混雑、口コミ、同行者の希望が強い。写真フィードの視聴時間を目的にせず、「料理を選べた」「行ける店舗を選べた」までの到達率と時間を主要評価にする。

### 3. 発見と検証では、求められる情報の鮮度が違う

発見コンテンツは感覚的でも機能するが、営業中か、価格はいくらか、予約できるか、決済方法、席、子ども対応、アレルゲン情報などは誤りが実害になる（JP-002、JP-007、JP-012、JP-013、JP-043、JP-051）。店舗情報には出典と確認日時を持ち、不明を推測で埋めない。重大な条件は店舗公式または予約先へ確認する導線を出す。

### 4. 信頼は平均点一つでは作れない

利用者は点数に加えて、レビュー本文、写真、件数、鮮度、具体性、悪い点、投稿者、店舗返信、複数媒体の一致を見ている（JP-005〜008、JP-018、JP-020〜024、GL-001〜007）。スポンサー枠、公式投稿、一般利用者投稿、インフルエンサー投稿、AI 要約を見分けられる表示が必要。要約には原文への導線を残し、評価値の取得元と更新日を示す。

### 5. 保存は価値仮説であり、来店効果はまだ証明されていない

Instagram コレクション、スクリーンショット、Google マップへの保存は広く使われる（JP-001、JP-002）。しかし、外部調査からは「保存した候補を後で見つけられるか」「保存が来店を増やすか」「料理と店舗のどちらを保存すべきか」は分からない。`行きたい`、`行った`、`いつもの`、`人に勧めたい` を混同せず、自社の日記調査と行動ログで検証する。

### 6. グループ選びは平均的な好みより制約の調整

デート、友人、団体、家族、一人、仕事相手で価格・雰囲気・アクセス・子ども対応などの重みが変わる（JP-013、JP-014、JP-033〜039、AC-013）。特に移動時間は一人の平均ではなく、最も遠い人を含む集団負担が効く可能性がある。投票機能は票数だけでなく、アレルギー、予算上限、移動上限、絶対に避けたい条件を先に扱うべきかを検証する。

### 7. 再来店は新規発見とは別のプロダクト課題

短期間の外食は再来店が多数を占め、味、コストパフォーマンス、馴染み、立地が重要になる（JP-009〜011、JP-027〜028、JP-035〜037、AC-001〜002）。新規店の発見だけを増やすと、日常の「いつもの店をすぐ決めたい」を取り逃がす。新規探索と再訪ショートカットを分けて計測する。

### 8. 文脈を入力できることが、プロフィール精度より先

同じ人でも、昼食、デート、家族、団体、旅行、時間不足、節約、特別な日で選択軸が変わる（JP-009、JP-013〜017、JP-033〜039、AC-001〜003）。固定的な「好きなジャンル」だけで個人化せず、今回の同行者、予算、時間、距離、気分、挑戦度を軽く指定できるようにする。

### 9. AI 提案への関心はあるが、利用意向と信頼を分けて測る

将来の AI 提案・予約への関心を示す調査がある一方、AI 生成レビューや要約への警戒も強い（JP-024、JP-031、GL-007〜009）。「AI を使いたいか」だけでは採否を決めない。候補の妥当性、根拠理解、修正可能性、決定時間、実来店、誤情報率を対照実験で測る。

### 10. 事業化は信頼を壊さない順序で検証する

外部調査は、予約の需要、ポイント・クーポンへの反応、特別体験への支払意向、店舗からの個別連絡への関心を示す（JP-012、JP-030〜031、JP-036〜047、GL-008〜009）。ただし、それだけで「なに食べよ」の広告、送客手数料、利用者課金の成立は証明できない。まず意思決定成功と来店を測り、次に以下を分離して検証する。

| 仮説                           | 顧客              | 価値                           | 最初に測るもの               | 主なガードレール                 |
| ------------------------------ | ----------------- | ------------------------------ | ---------------------------- | -------------------------------- |
| 予約・地図・公式サイトへの送客 | 店舗 / 予約事業者 | 意思決定済み需要               | 外部遷移後の予約・来店確認   | ランキングへの報酬混入禁止       |
| 明示されたスポンサー枠         | 店舗              | 新規発見                       | 広告認知、保存、来店、非表示 | 広告ラベル理解、自然結果への影響 |
| 消費者向けプレミアム           | 利用者            | 高度な共同選択、整理、制約管理 | 支払意向ではなく有料試用継続 | 無料の中核決定体験を壊さない     |
| 匿名集計インサイト             | 店舗 / 本部       | 需要・離脱の理解               | 意思決定に使えるか           | 少数セル抑制、同意、再識別防止   |

## 意思決定ファネルと推奨指標

| 段階         | 利用者の仕事           | 主要指標                 | 診断指標                                       |
| ------------ | ---------------------- | ------------------------ | ---------------------------------------------- |
| 起動         | 今回の条件を伝える     | 条件入力完了率           | 位置許諾拒否、離脱項目、入力時間               |
| 料理発見     | 食べたい方向を見つける | 料理決定率、決定時間     | スワイプ数、深掘り、候補なし、戻る             |
| 店舗絞り込み | 現実に行ける店を選ぶ   | 店舗決定率               | 価格・距離・営業時間確認、口コミ閲覧、除外理由 |
| 合意         | 同行者と決める         | グループ決定率、合意時間 | 招待開封、参加率、拒否条件、同率               |
| 行動         | 店へ向かう・予約する   | 有効アクション率         | 地図、電話、予約、公式サイトへの遷移           |
| 来店         | 実際に利用する         | 来店確認率               | 自己申告、位置を使わない確認、キャンセル理由   |
| 再利用       | 保存・履歴を次回使う   | 30 日内の再決定率        | 保存再閲覧、いつもの店利用、新規と再訪の比率   |

北極星候補は **「有効な食事決定数」**。同一セッションで料理と店舗を選び、有効アクションに進み、後日の軽い確認で来店または予約が確認できた件数と定義する。位置履歴の常時収集を前提にせず、指標の妥当性自体を `OUT` 系設問と実験で検証する。

### 経営ダッシュボードのガードレール

- 店舗情報の誤り・古さの報告率
- スポンサー表示を正しく認識した割合
- 推薦後に「候補が偏っている」と回答した割合
- アレルギー・食事制約に関する誤表示件数
- 通知停止率、退会率、投稿・保存の非公開設定率
- 新規店だけでなく個人店・低露出店へ機会が配分されているか

## まだ外部調査では答えられない重要事項

次は既存資料から推論して実装を決めず、自社調査を先に行う。

| 優先度 | 未確定事項                                             | 最小の検証                             |
| ------ | ------------------------------------------------------ | -------------------------------------- |
| P0     | 料理から選ぶ流れが店名検索より速く、満足できるか       | 現行プロトタイプ対自由検索のタスク比較 |
| P0     | 6 料理候補・5 店舗候補が適切か                         | 候補数 3 / 6 / 10 の無作為比較         |
| P0     | 正確性に必要な最小店舗情報は何か                       | 直近外食の再現面接 + 情報欠落テスト    |
| P0     | 推薦理由と出典表示が信頼・決定を改善するか             | 理由なし / 短い理由 / 根拠展開の比較   |
| P1     | 保存した料理・投稿・店舗の分類が利用者の記憶と合うか   | カードソート + 14 日日記調査           |
| P1     | 保存が再閲覧・来店につながるか                         | 保存後 1 / 7 / 30 日の再訪と来店確認   |
| P1     | グループ投票が会話より早く、公平に決まるか             | 実在グループによる会話のみとの比較     |
| P1     | 縦フィードが意思決定を助けるか、先延ばしを増やすか     | 決定時間・後悔・候補多すぎ感の比較     |
| P1     | `いつもの店` と `行きたい店` を分ける価値              | ラベルなし / 二分 / 四分の概念テスト   |
| P1     | ログイン前にどこまで価値を体験させるべきか             | 保存・投票・投稿ごとのログイン壁比較   |
| P2     | AI 要約・AI コンシェルジュを日本の利用者が信頼する条件 | 出典、訂正、説明、非 AI の対照実験     |
| P2     | 広告・送客・有料機能の許容範囲                         | 実価格を伴う選択実験と広告認知テスト   |

## 推奨する調査順序

1. **探索面接 20〜30 人**: 直近の一回を画面履歴とともに再現し、言語化されていない迂回・不安・妥協を集める。
2. **全国基準調査 1,200 人程度**: 18〜69 歳の性・年代・地域を割り付け、Z 世代は分析可能な数まで追加する。一般母集団と SNS 利用者を分ける。
3. **14 日日記調査 150 人程度**: 発見、保存、相談、予約、来店、再訪を同じ意思決定 ID で追う。
4. **コンセプト比較 600 人程度**: 料理先行、店舗先行、AI 対話、フィードの複数案を無作為提示する。
5. **実在グループ調査 12〜20 組**: 友人、カップル、家族、職場で投票と拒否条件の扱いを観察する。
6. **プロダクト内実験**: 自己申告だけでなく決定時間、外部遷移、再閲覧、来店確認を測る。

一度のアンケートに全設問を入れない。スクリーナーと直近一回の行動を共通核にし、回答者をモジュールへ無作為配分する。推奨質問文と分岐は [自社アンケート設問バンク](nanitabeyo-survey-question-bank.md) にある。

## 読み方と証拠強度

カタログの評価は論文や調査会社の優劣ではなく、今回の問いに再利用できる度合いを表す。

| 評価 | 目安                                                         | 使い方                                                   |
| ---- | ------------------------------------------------------------ | -------------------------------------------------------- |
| A    | 公的統計、査読研究、無作為実験、方法が十分公開された代表調査 | 方向性の根拠。ただし国・年代・実験環境の外挿は別途確認   |
| B    | 一次公開で母集団・時期・標本数が明確                         | 仮説と質問設計に使用。ベンダー利害と自己申告を考慮       |
| C    | 条件付き標本、小標本、分母・方法の一部不足、会員調査         | セグメント仮説と選択肢生成に使用。市場全体へ一般化しない |
| D    | 二次記事しか確認できない、または方法がほぼ不明               | 設問の着想だけに使用。数値を意思決定根拠にしない         |

異なる調査の割合を単純比較しない。複数回答か単一回答か、一般人口か SNS 利用者か、利用経験者だけか、質問文、調査年、地域が違えば分母も意味も異なる。特に「使う」「信頼する」「行きたい」は実際の来店と同義ではない。

## 更新手順

1. 原典を開き、調査主体、実施日、対象、標本数、質問形式、分母を確認する。
2. カタログへ新しい ID を追加し、既存系列なら過去年へのリンクを付ける。
3. 数値はカタログだけに記録し、他文書では ID を参照する。
4. 結論が変わる場合だけこの README を更新し、変更理由をコミットまたは PR に書く。
5. 自社で検証済みになった問いは設問バンクに結果への参照を付け、外部調査と自社データを混ぜない。

### 探索の停止条件

今回の探索は、発見、検証、料理選択、保存、同行者、再来店、予約、家族・制約、信頼、AI、収益化の各領域で一次資料が複数得られ、新規検索が既知系列か低情報の転載を返す状態になったため停止した。次回は 2026-12-01 以降の新規調査、または上表の未確定事項に直接答える研究だけを追加候補にする。
